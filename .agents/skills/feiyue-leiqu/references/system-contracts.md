# 三工程系统契约

## 责任边界

| 系统 | 拥有的决定 | 不应拥有的决定 |
|---|---|---|
| 飞控 CM7_0 | 主摄流水线编排、主副摄选择、信标任务选择、共享发布、A4发布 | 姿态/高度/电机闭环 |
| 飞控 CM7_1 | 传感器、估计、姿态/高度/水平控制、混控、安全和任务时间轴 | 复杂图像识别与阻塞显示 |
| 小车 | 外部命令仲裁、视觉租约、车体速度成形、Yaw保持、轮速闭环、硬停车 | 飞行安全与主副摄目标选择 |
| 副摄 | 图像识别、镜头校正、安装映射、B2快照 | 最终任务锁、A4发布或执行器控制 |

跨层需求先落到拥有该决定的系统。不要为了少改一个仓库把业务判断塞进协议 Adapter 或 ISR。

## 通讯契约

- A4：飞控向小车发布视觉和任务语义；`MISSION_STOP` 是高优先级锁存安全语义。
- C5：小车向飞控发布车体运动参考；测量、有限前馈、坐标和新鲜度必须可区分。
- B1：主板向副摄发起请求并携带请求身份/模式。
- B2：副摄回传当前感知快照和映射向量；飞控仍负责是否采用。
- 飞控共享内存：CM7_0 与 CM7_1 的内部 ABI；布局、版本、地址、大小断言和缓存维护必须同步。

具体长度、字段、位定义、端序、频率和超时从当前协议文档与两端源码读取，不在 skill 中冻结副本。

任何线格式变化都要列出：生产者、消费者、旧端点行为、版本策略、配套构建、配套烧录和文档同步。控制参数变化不应顺便改变线格式。

## 坐标契约

至少区分：

1. 主摄/副摄各自图像坐标。
2. 鱼眼校正后的控制点或相对向量。
3. 副摄安装角映射后的主摄方向向量。
4. 飞控内部水平纠偏坐标。
5. 光流传感器坐标与机体坐标。
6. 小车公开车体坐标与内部历史变量命名。
7. 逻辑电机/轮序与物理通道。

每条边界用显式 Adapter 和方向试验验证一次。禁止依据变量名猜方向，禁止在下游重复镜头校正，禁止用混控或麦轮公式补偿单个物理通道接反。

## 时间与有效性契约

对每类数据同时回答：

- 是否收到字节或采样；
- 是否形成完整帧；
- 校验和范围是否合法；
- 是否为新帧；
- 测量是否可信；
- 是否处于 hold；
- 是否已稳定发布；
- 是否被任务层选用；
- 控制租约是否仍有效。

“短时没有视觉测量”和“通讯断线”不是同一状态；“收到完整坏帧”和“没有新帧”也不是同一状态。

## 发布与兼容

三个仓库保持独立，但跨仓功能按匹配版本发布。协议、坐标、视觉算法共享语义或安全位变化时，建立兼容矩阵并明确是否必须三端一起烧录。没有验证旧端点行为时，不声称向后兼容。
