# 小车开发经验

## 安全与模式仲裁

小车首先是执行器系统。明确单一优先级，通常包含：锁存安全停车、有效无人机任务、手动控制、普通待机。调参不得绕过高优先级硬零路径。

- `MISSION_STOP` 一旦合法锁存，普通 A4、视觉续航和遥控不能意外重启四轮；只有明确设计的维护/调试路径可以例外。
- `SAFE_STOP` 是四轮零输出，不是带 Yaw 保持的“看似停车”。
- 视觉短时丢失、A4 整链路超时和用户主动停车是三个状态，分别处理。
- 模式重入不得用未经滤波的瞬时里程计或陈旧方向跳过速度斜坡。

## 坐标、轮序与执行边界

- 对外协议使用明确的 `forward/right` 语义，不让历史变量名决定方向。
- 车体速度到四轮目标由唯一麦轮运动学完成；四轮逻辑顺序到板级电机/编码器通道由硬件 Adapter 完成。
- 单轮接线或编码器符号错误只修该通道，不能扭曲整套麦轮公式来补偿。
- 首次烧录架空四轮，验证前、后、左、右、旋转以及编码器回读方向。

## 平顺而快速的控制链

建议链路：

`外部方向/速度请求 -> 方向滤波 -> 分轴或矢量限速 -> 加减速成形 -> 麦轮分解 -> 单轮速度PID/前馈 -> duty保护 -> 电机`

- 自动追踪速度、前后/左右比例、加速度和压灯参数解决不同问题，不要用一个总速度宏掩盖方向差异。
- 限加速度作用于车体速度矢量，保证方向变化连续；单轮 duty 变化保护是下游执行器保护，不能代替上游运动成形。
- 静摩擦前馈用于克服死区，不应承担速度闭环全部工作。轮速 PID 调整先在架空/低负载单轮和直行中验证。
- Yaw 保持用于抵抗底盘偏航，安全停车时必须让位于硬零。

## 追灯、续航与压灯

- 视觉任务使用最后一次已接受的 V→B 方向，不直接消费未经任务确认的亮点。
- 短时视觉缺失可在有界租约内保持已成形命令，然后衰减；没有曾接受方向时不得盲走。
- A4 链路真正超时必须比视觉 hold 更明确地停车，不能让长视觉租约隐藏断线。
- 近灯压灭与远区追踪、丢灯续航互斥；进入压灯后限定方向修正、时长和下一目标接管条件，避免压灭后继续冲刺。

## 与无人机共同调参

小车速度不是独立 KPI。无人机必须有追赶余量、姿态余量和视场余量。

调节顺序：

1. 小车自身四轮与里程计稳定。
2. 慢速固定方向，确认 A4 坐标。
3. 限制前向速度和加速度，使无人机能建立姿态而不拉紧挂线。
4. 分别测起步、匀速、停车、反向、横向。
5. 再增加速度或缩短响应时间。

C5 常态以实测里程计为基础。若加入前馈，只在证据明确的事件和方向中有限混合，制动、反向、横向和手动是否仍为实测必须明确。C5 不应成为改变小车自身运动的隐蔽反馈环。

## 症状定位

- 小车一卡一卡：同时检查 A4 `MOVE_VALID`、真实链路新鲜度、任务状态重入和速度成形是否重置。
- 起步突跳：检查模式重入播种、方向滤波初始化、矢量 slew 和 duty 限制，而非先降轮速 PID。
- 直行偏航：区分轮速/摩擦差异、编码器符号、Yaw 估计和麦轮几何。
- 压灯后继续走：查压灯状态退出、租约清理、任务目标接管与硬停车优先级。
