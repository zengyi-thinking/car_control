# 快速接手三工程

## 先识别工作范围

三工程通常以同级独立 Git 仓库存在：

- `flight_control`：无人机主板，CM7_0 偏主摄感知与发布，CM7_1 偏飞行估计、控制和任务。
- `car_control`：麦克纳姆小车，负责 A3/A4 仲裁、车体运动、轮速闭环和 C5 反馈。
- `camera_helper`：副摄板，负责灰度视觉和 B1/B2 应答，不拥有任务决策。

用户只要求一个仓库时，只读检查相关端点，除非行为或接口必须配套修改。跨仓改动要先列出每个仓库的写集合。

## 十分钟恢复流程

三仓同级存在时，可先从当前 skill 目录运行只读快照：

```powershell
pwsh -File scripts/inspect-suite.ps1
```

从仓库镜像运行时脚本会自动找到同级套件；独立发布目录无法推断工程位置时，显式传入 `-SuiteRoot`。快照只做发现，不替代后续源码核对。

在每个实际涉及的仓库中：

1. 读 `AGENTS.md` 和 `README.md`。
2. 查看 `git status --short --branch` 与最近提交，不覆盖未提交修改。
3. 若有 `CONTINUITY.md`，只读顶部当前状态与 open loops；若有 `decisions.md`，按主题检索最新决定。
4. 查实际 `iar/` 脚本，不照抄历史文件名。
5. 查 `hw_config.h`、协议实现和维护中的协议/坐标文档，确认当前默认值与接口。
6. 写下五项基线：当前实现、最近构建、最近物理验证、未闭环风险、需配套的固件版本。

涉及飞控架构或新任务时，再读取当前模块地图、双核入口和任务仲裁点；不要因旧任务文件名看似相近就直接追加分支。

## 事实优先级

- 实时代码、配置和构建脚本证明当前分支实现。
- 最新未被取代的决定和当前状态证明设计意图与验证结论。
- 协议两端实现与维护中的协议文档共同证明线契约。
- 历史记录只用于失败教训和回退背景，不定义当前参数。

发现冲突时明确指出，不静默挑选有利来源，也不顺手重写无关历史。

## 常见入口

显式调用：

```text
$feiyue-leiqu 分析无人机前向追车为什么落后
$feiyue-leiqu 在不改变A4格式的前提下让小车起步更平顺
$feiyue-leiqu 提升副摄远距信标识别，同时控制误检
$feiyue-leiqu 审查这次B1/B2协议修改需要哪些配套验证
$feiyue-leiqu 新增一个飞行任务，并说明归属、优先级、状态机和安全退出
```

只做状态查询或诊断时不要改代码；用户要求实现时，才执行最小修改和相应验证。

## 快速配置原则

- 开发者无需把仓库 skill 安装到个人目录；在仓库内启动 Codex 即可自动发现。
- IAR、调试器和本机 C-SPY 设置仍按各仓库 README 配置，skill 不替代硬件工具链。
- 三仓匹配发布时先核对协议、坐标和功能开关，再分别构建；共享内存变化还必须同时更新飞控双核。
- 个人实验参数不要写进 skill。可调默认值留在各自 `hw_config.h`，试验结论留在当前状态或决策记录。
