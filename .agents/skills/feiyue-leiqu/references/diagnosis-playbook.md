# 跨系统诊断手册

## 先把症状写成可证伪描述

至少包含：当前模式、运动方向、发生时刻、持续时间、数据新鲜度、实际物理布置和相邻两层观测。把“看起来不稳定”改写为“目标 Roll 为负而实际 Roll 为正”或“B2 收包持续增长但任务选中目标不更新”。

## 第一分歧点方法

按顺序检查并在第一处异常停止：

1. 原始输入是否存在，方向、量级和时间是否合理。
2. 完整帧、校验、frame ID 与新鲜度是否合法。
3. 硬件/算法是否因可解释原因接受或拒绝测量。
4. 估计与稳定发布是否跟随真实新测量，而不是陈旧 hold。
5. 任务/模式层是否选择了预期目标或命令源。
6. 目标成形、限幅和安全门是否保留正确方向。
7. 控制器、运动学、混控、slew 和传输是否正确执行。
8. 物理系统是否按命令响应。

不要用后层增益补偿前层语义错误。

## 最小插桩原则

优先复用已有状态行和遥测。缺少证据时，在两个相邻边界各增加一个低频、有限长度、可撤回的观测量；不要在高速 ISR 打印，不要同时扩展共享内存、串口协议和屏幕布局。

好插桩能在一次测试中区分假设，例如：

- 视觉误差 / 成形目标速度 / EKF速度；
- 目标姿态 / 实际姿态；
- 请求 duty / 混控后 duty / 编码帧；
- raw ToF / reject 原因 / 高度状态；
- 检测候选 / 发布目标 / 任务选中目标 / A4或B2 flags；
- 车体目标速度 / slew后速度 / 轮速目标 / 编码器速度。

## 常见分叉

### 看到了但不控制

检查显示是否为 hold、控制目标是否真实、共享/协议是否新鲜、任务层是否选用、模式门是否满足。不要先增大追踪增益。

### 命令方向正确但实际反向

问题位于控制输出之后或姿态估计本身：检查负反馈极性、混控/轮序、执行器权威、重心和挂线力矩、接线、桨/轮与传感器污染。

### 短时停顿或周期性启停

对齐 frame ID、视觉有效位、链路年龄、模式切换、状态重置和速度/姿态 slew。区分数据闪断、重复快照和真正链路超时。

### 单个执行器异常

记录所有逻辑输出和物理通道映射。软件无单路切断且帧为同批发送时，进行温度、换位、线束、负载和替换板试验。异常跟随部件还是留在通道，是高价值证据。

### 识别率与误检互相拉扯

分场景统计严格检测、局部恢复、回退和发布。先修状态冻结与冲突裁决，再局部放宽；一次全局阈值变化很难同时解决远距弱灯和环境亮点。
