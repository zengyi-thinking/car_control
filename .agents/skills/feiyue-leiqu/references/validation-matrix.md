# 验证矩阵

## 按改动选择验证

| 改动 | 软件验证 | 物理/配套验证 |
|---|---|---|
| skill、普通文档、纯注释 | skill审计、链接、diff检查 | 无 |
| 单一可调宏且无接口/语法风险 | diff与约束检查；按仓库规则决定是否构建 | 对应行为的低风险实测 |
| 控制环、估计器、状态机、混控、任务逻辑 | 受影响仓库双核构建，0错误0警告 | 方向相关先拆桨/架空，再系留或地面测试 |
| 传感器驱动、解析、初始化和时序 | 双核构建；检查 ISR/低速服务边界和坏帧/无帧语义 | 台架数据与新鲜度测试，再进入控制 |
| 飞控共享内存 | 两核构建；核对版本、大小断言、地址和缓存操作 | CM7_0/CM7_1 配套烧录，禁止混版 |
| A4/C5 | 飞控与小车相关端点构建；核对端序、字段、flags、校验、frame ID、新鲜度 | 配套烧录，验证断线、坏帧和停止语义 |
| B1/B2或共享视觉算法 | 飞控与副摄构建；比较共同算法合同 | 配套烧录，做四方向、遮挡、接管和恢复测试 |
| 坐标、IMU轴、光流符号、电机/轮序、Yaw极性 | 构建并审查唯一 Adapter | 强制拆桨/架空方向试验和负反馈测试 |
| 安全停车、disarm、failsafe、硬零 | 构建并逐条触发安全转移 | 任何带动力测试前先台架验证 |
| IAR工程或API签名 | 运行当前仓库实际完整构建入口 | 检查两个 target 与下载配置 |

## 构建原则

- 从当前 `README.md` 和 `iar/` 发现实际命令，不信任历史记录中的旧脚本名。
- 只保留首个错误及相关上下文，不把完整日志写入对话或长期记忆。
- IAR 不可用时明确写“未运行”，不得推断通过。
- 文档和 skill 改动不需要浪费时间编译固件。

## 物理验证阶梯

1. 静态审查与配置约束。
2. 纯算法/主机测试或离线帧回放。
3. 双核构建。
4. 拆桨、架空轮组、手持传感器和协议台架。
5. 低功率系留或受限地面测试。
6. 单方向、低速度、低高度测试。
7. 起步、匀速、停车、反向、失效与接管。
8. 最后扩展速度和完整任务包络。

带动力测试准备独立断电/急停手段。某一级通过不能替代更高一级。

## 跨仓完成检查

- 谁生产、谁消费、谁拥有最终决策？
- 单位、尺度、坐标、端序、有效性和新鲜度是否显式？
- 旧端点收到新帧或新端点收到旧帧会怎样？
- 哪些仓库、核心和板卡必须一起构建与烧录？
- 协议、坐标、README、屏幕和遥测是否需要同步？
- 安全路径是否在无数据、坏数据、陈旧数据和重启情况下仍成立？

## 结论用语

优先使用：

- `已实现，未构建`
- `双核构建通过`
- `架空/拆桨验证待进行或已通过`
- `系留/地面验证待进行或已通过`
- `在所述速度、高度、方向和场景内实测通过`
- `候选被否定并已撤回`

没有达到相应证据时，不使用“已经修好”“安全”“可直接飞”等表达。
