# 飞控开发经验

## 架构与实时边界

- `application` 负责编排和生命周期，`algorithm` 做纯计算，`hardware` 封装设备与协议，`user` 只做启动、周期和 IRQ。
- 高速控制 tick 只消费已经缓存的短数据并完成估计、控制和执行器提交。软 I2C、串口大事务、显示和文本格式化放低速服务。
- 控制状态由明确结构和模块私有状态传递，不让多个 application 分支直接争用控制器内部变量。

## 调试控制链

逐层对齐：

`传感器原始值 -> 硬件有效状态 -> EKF/AHRS -> 位置/速度/姿态目标 -> 限幅与slew -> 角度环 -> 角速度环 -> 高度/姿态分配 -> 四电机 -> 实际姿态`

看到目标不等于控制层拥有新测量；目标姿态正确而实际姿态反向，不应继续修改视觉符号。目标和实际在同方向但跟不上，才考虑权威、尺度、负载和速度包络。

## 姿态与 AHRS

- 先验证 IMU 安装轴、角度符号、角速度符号和启动相对 Yaw，再调控制器。
- 加速度模长接近 1g 不代表它一定是重力；水平加速、挂线和碰撞会污染重力方向。可信度门应考虑创新方向，并限制低可信积分学习。
- Yaw 没有绝对航向源时只能保持相对启动方向。不要把陀螺长期漂移包装成绝对航向能力。

## 高度与 ToF

高度问题按 `raw -> reject原因 -> fresh/hold/invalid -> 融合高度 -> EKF -> 目标速度 -> 油门修正 -> 混控余量` 查找。

- 近物、地面、倾角、跳变和陈旧值必须在硬件语义层区分。
- 传感器冲突且无证据判断真源时宁可拒绝冲突对，也不要用“更接近旧滤波值”假装确定。
- 高度恢复和下降权限不能被水平追踪或 Yaw 调参无意吃掉。

## 光流与水平追踪

- 区分无帧、完整坏帧、创新拒绝和健康测量；健康度每真实时间步只结算一次。
- 多光流要保留独立测量和独立质量证据。相关性、有效率、静止噪声和手持方向未通过前，不因“有两路”就默认融合。
- 旋转补偿、传输延迟、安装偏心和高度尺度各有独立物理含义，不能复用一个补偿量。
- 视觉位置误差先生成有界目标速度，光流速度闭环再生成姿态目标。前馈用于减少延迟，不应覆盖真实反馈或绕过最终姿态/混控保护。

## 调参顺序

1. 电机映射与负反馈方向。
2. 姿态角速度环和角度环。
3. 高度估计与高度环。
4. 光流速度真实性和水平阻尼。
5. 静止视觉目标。
6. 慢速小车、起步、匀速、停车和反向。
7. 提速和复杂任务。

一次不要同时提高位置增益、速度增益、姿态上限和小车速度。先保留混控余量，再逐步放开。

## 混控、电机与物理系统

- 逻辑电机顺序、物理通道映射、单电机方向和 Yaw 对角极性是四个不同边界。
- 饱和分配优先保住 Roll/Pitch 和 collective，再决定 Yaw 可以使用多少余量；一个轴被裁剪不应无理由衰减其他轴积分。
- 明确停机路径必须绕过普通 slew 并硬零。普通快速卸载和显式停机不能混为一谈。
- 单电机短时掉速但软件四路命令和同帧传输正常时，用换位、温度、线束、桨、电调板和负载几何试验定位。

## 连续 Yaw 与任务时间轴

- 普通 Yaw 保持使用最短角误差；超过一圈的任务使用未折返累计角，不能进入普通 wrap 后退化为短路径。
- 使用硬件时间基准，不依赖循环次数累加任务秒数。
- 锚点捕获时刻、过渡窗口、传感器丢失策略、完成条件和最终保持必须明确。
- 物理方向错误先检查任务方向 Adapter；只有普通 Yaw 负反馈也错误时才改变混控极性。
