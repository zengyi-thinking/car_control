# 视觉与副摄开发经验

## 保持一条视觉语义链

将视觉结果分层：

`原始候选 -> 当前帧真实测量 -> 稳定控制结果 -> 稳定发布结果 -> 任务选择 -> 显示覆盖 -> 协议快照`

每层可能有不同的 `found`、hold、置信度和新鲜度。屏幕上的框不自动证明控制或通讯有效；纯 hold 不能更新世界锚点、双摄映射或真实运动观测。

## V灯与信标分类

- V灯与信标可能在远距、过曝、边缘或遮挡时退化成相似亮斑。优先使用形状、局部几何、时序活动和空间独立证据，避免用一个全局亮度阈值解决所有场景。
- 恢复链应有范围：严格检测失败后，只在最近可信轨迹附近做局部恢复；全图弱证据回退必须更保守。
- V/B 冲突裁决集中在共同算法层，主摄和副摄不要各写一套分类政策。
- 置信度低不等于位置不真实。确认层要避免因检测来源交替或单帧 hold 把连续位置候选永久清零。
- 多候选检测与最终单目标发布分开；任务层维护身份，但不要重复算法层已经完成的同类确认。

## 提升识别率而不扩大误检

先收集可复现证据：原始灰度帧、候选 bbox/中心/置信度/来源、环境位置、距离、曝光和失败类别。一次只调整一个判据族。

优先顺序：

1. 修复候选被冻结、被错误忽略或未发布等状态 bug。
2. 在已知轨迹 ROI 内增强恢复。
3. 用径向、局部背景或时序证据处理镜头边缘与漫射灯罩。
4. 最后才放宽全图几何或亮度门槛。

每次同时验证：真 V、真信标、V 与信标靠近、静态环境灯、边缘反光、短遮挡和远距弱目标。只报告构建不能证明识别率提升；没有帧回放集时明确要求实物回归。

## 主副摄共享与差异

- 两边的纯视觉算法源应保持同一合同；允许的差异只在相机应用、显示、UART Adapter、安装旋转和明确配置。
- 修改共同算法后比较两仓同名文件或共享测试结果，防止只修一端。
- 副摄持续产生最新快照并快速响应 B1；飞控依据不同视觉 frame ID、新鲜度、身份连续性和任务阶段决定是否采用。
- 主摄恢复不能接管到错误信标；进入近距压灯等不可逆阶段后，副摄接管规则应更保守。
- 显示颜色和连线应来自最终语义层。临时候选不能显示成“已采用”，否则现场诊断会被误导。

## 镜头与安装映射

- 在每个摄像头自身坐标内分别校正 V 点和 B 点，再求相对向量。
- 安装角映射只做一次；飞控收到副摄已映射向量后不得再次套主摄镜头模型。
- 无标定板时，鱼眼模型和最大放大属于保守候选，不应被描述成精确标定。
- 方向验证用 V 固定、B 分别位于右/下/左/上四个位置，逐层检查原始向量、校正向量、安装映射和最终任务方向。

## 性能与通讯

- 图像采集和算法每帧运行；显示应分频、缓存并避免阻塞发布。
- UART ISR 只收字节或推进小解析器，不做图像算法和复杂格式化。
- B2 中当前测量、快照新鲜、映射有效和 frame ID 各有独立意义。重复回复同一快照不能算多帧视觉确认。
- 心跳证明链路活着，不证明目标存在；请求应答成功也不证明飞控任务层采用了该目标。
