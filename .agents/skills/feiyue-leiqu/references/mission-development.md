# 飞行任务开发规范

飞行任务是带触发、状态、优先级、时间语义和安全退出的应用层能力，不是一组散落在控制器中的条件分支。新任务先形成任务契约，再修改代码。

## 先判断需求属于哪一层

- “看见什么、选哪个目标”：CM7_0 感知或任务选择。
- “何时起飞、追踪、旋转、下降、停止”：CM7_1 飞行任务。
- “怎样把位置/速度误差变成姿态目标”：水平或高度引导。
- “怎样跟踪姿态、高度和角速度”：控制算法。
- “怎样驱动电机或传输帧”：硬件适配。
- “小车怎样响应任务并安全停车”：小车应用与控制。

一个需求可以跨层，但每个决定只有一个所有者。不要为了少改一个端点，把任务判断塞进协议 Adapter、视觉算法、PID 或 ISR。

## 任务契约

实现前写清以下内容；不能回答时先调查，不直接编码。

| 字段 | 必须说明 |
|---|---|
| 所有者 | 仓库、核心、应用模块和唯一仲裁点 |
| 目标 | 可观测的完成结果与适用包络 |
| 触发 | 事件、时间、模式、操作员命令及前置健康条件 |
| 状态 | 每个状态的职责、进入条件、退出条件和非法转移 |
| 输入 | 单位、坐标、frame ID、新鲜度、可信度与 hold 语义 |
| 输出 | 高度、Roll/Pitch、Yaw、停车位、视觉身份或协议意图 |
| 优先级 | 能抢占谁、被谁抢占、是否允许并行 |
| 时间 | 硬件时间基准、超时、截止、暂停与重启语义 |
| 失败 | 无帧、坏帧、陈旧、传感器无效、通信断线和任务超时 |
| 结束 | 完成保持、恢复旧模式、硬停、复位和再次启动规则 |
| 观测 | 状态、原因、目标、实际量、饱和与健康字段 |
| 发布 | 受影响核心、仓库、协议版本、构建、烧录和物理验证 |

当前宏值、时间点和增益不进入契约模板；它们继续由当前配置维护。

## 状态机规则

- 使用显式枚举和单一私有状态；初始化、启动、周期更新、查询和复位接口按实际需要提供。
- 每次转移说明触发事件与副作用。进入状态时捕获的锚点不得在普通周期中悄悄重捕。
- 使用硬件时间差处理持续时间，不用循环次数推算秒数，也不依赖低频视觉帧推进飞行时间轴。
- 将“当前帧丢失”“短时 hold”“链路超时”“传感器无效”和“任务失败”分开。
- 任务完成后的保持目标必须明确；若恢复旧模式，要重新播种目标和成形器，避免跳变。
- 支持重启的任务必须清理积分、缓存、租约、锁存和旧 frame ID；不可重启的任务要明确锁存边界。

## 唯一仲裁与抢占

顶层仲裁保持单一入口。安全停机、明确降落或失效保护优先于普通任务；业务任务再按风险和控制权排序，最后回到悬停/零速保持。

加入新任务时列出完整优先级表，不只写“高于追车”。抢占至少处理：

1. 被抢占任务是否暂停、失败还是结束。
2. 目标高度、姿态、Yaw 和位置锚点如何连续交接。
3. 是否清除视觉租约、车速前馈、积分和 slew 状态。
4. 高优先级状态解除后是否允许自动恢复。
5. CM7_0、小车或副摄是否需要收到新的任务语义。

任务模块不得直接调用电机。它输出有界任务意图，由既有引导、控制、混控和安全路径执行。

## 输入有效性与控制降级

每个任务为关键输入定义阶梯：

`新鲜可信测量 -> 有界短时保持 -> 明确降级目标 -> 安全退出或继续独立时间轴`

哪种策略适用取决于任务。视觉闪断不一定暂停定时 Yaw；高度无效却可能禁止下降；A4/C5 断线与单帧漏检也不能共享一个计数器。降级不得把旧数据伪装成新测量。

## 实时集成

- 高速控制 tick 只消费任务模块已经缓存的短目标，并保持原有估计、控制、提交顺序。
- 较重的共享包读取、状态决策、诊断组包和慢速传感器服务放在低速通道。
- CM7_0 的图像任务由新帧驱动；飞行任务时间轴由 CM7_1 硬件时基驱动。
- 跨核只传最小、命名清晰且有版本的任务语义；不要借用无关字段。
- 对同一复合状态的跨上下文读写使用快照或短临界区，不在 ISR 中持有长临界区。

## 观测与验收

至少能观察：当前任务与状态、转移原因、关键输入年龄、目标/实际高度与姿态、控制饱和、安全位和跨核发布状态。优先复用已有反馈与屏幕，新增观测保持低频、有界、可撤回。

验证按风险逐级进行：

1. 状态转移和配置约束静态审查。
2. 时间边界、角度跨界、无帧/坏帧/陈旧和重启的主机或台架测试。
3. 受影响核心与仓库完整构建。
4. 拆桨检查目标、协议位、抢占、硬零和电机方向。
5. 系留或架空检查连续交接、姿态/高度余量和停止条件。
6. 单方向、低速、低高度实测，再扩展完整任务包络。

结束报告必须列出最高证据等级和未完成的物理验证，不能用状态机代码完整或构建通过代替任务验收。

## 典型错误

- 在控制器内部根据业务时间切换增益或目标。
- 在 CM7_0 和 CM7_1 各维护一份任务倒计时。
- 新任务直接覆盖姿态目标，却不经过唯一仲裁和 slew。
- 用显示框或 hold 结果刷新真实测量锚点。
- 只验证正常完成，不验证抢占、断线、重启和传感器失效。
- 同时改变任务逻辑、协议、控制增益和物理方向，导致无法判定第一分歧。
