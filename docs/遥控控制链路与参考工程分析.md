# 遥控控制链路与参考工程分析

## 1. 目的
本文把当前 `car_control` 工程里“遥控器如何让小车运动”的细节完整拆开，并把 `references` 目录中的两个参考工程对应到具体文件。

后续如果要把这套遥控输入迁移到无人机，这份文档可以直接当成“输入链路分析图”和“文件索引表”使用。

## 2. 当前工程的遥控链路

### 2.1 遥控帧入口

当前工程使用 LoRa 遥控串口帧，解析入口在下面两个文件：

- [code/protocol/proto_remote.h](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/code/protocol/proto_remote.h)
- [code/protocol/proto_remote.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/code/protocol/proto_remote.c)

帧格式要点：

- 帧头：`0xA3`
- 数据：`joystick[4]`、`key[4]`、`switch_key[4]`
- 解析后输出到 `proto_remote_data_t`

这一步只负责“把串口字节变成遥控数据结构”，不直接控制电机。

### 2.2 遥控数据如何进入控制层

遥控数据在应用层被定期拉取，并送入底盘控制：

- [code/app/app_car.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/code/app/app_car.c)

关键流程：

- `proto_remote_update()` 取出最新遥控帧
- `app_car_step()` 里把遥控数据和年龄值送给 `chassis_control_set_remote()`
- 同时把当前模式、导航数据一起送给 `chassis_control_step()`

### 2.3 遥控器怎么影响小车运动

核心控制在：

- [code/control/chassis_control.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/code/control/chassis_control.c)
- [code/control/chassis_control.h](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/code/control/chassis_control.h)

当前工程里，遥控器不是“直接驱动电机”，而是分成两条语义链：

1. 左摇杆走手动速度通道
2. 右摇杆走位移编辑/定点通道

#### 左摇杆手动通道

手动模式下，左摇杆被归一化后映射成底盘速度命令：

- `joy_x_norm`、`joy_y_norm` 由遥控器摇杆计算
- `user_cmd_x_mps`、`user_cmd_y_mps` 由摇杆归一化值乘以手动最大速度得到
- 再转换成 `vx_body_cmd`、`vy_body_cmd`

然后由麦轮逆解换成四轮目标速度。

#### 右摇杆位移通道

右摇杆当前用于编辑 `DX / DY` 位移目标：

- 上下改变 `position_edit_dy_m`
- 左右改变 `position_edit_dx_m`
- 按下右摇杆按键后提交目标点

提交后控制器进入位姿执行状态，由当前位置误差生成平移速度命令，再做四轮逆解。

### 2.4 从速度命令到电机输出

这条链路是：

- `chassis_control_step()`
- `mecanum_inverse()`
- 四轮 PID
- `hw_motor_drv8701e_set_all()`
- PWM 输出到电机驱动

对应文件：

- [code/control/mecanum.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/code/control/mecanum.c)
- [code/control/pid.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/code/control/pid.c)
- [code/hardware/hw_motor_drv8701e.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/code/hardware/hw_motor_drv8701e.c)

控制顺序可以概括为：

1. 遥控输入解析成 `proto_remote_data_t`
2. 应用层把遥控和导航数据喂给底盘控制
3. 底盘控制根据当前模式决定手动还是位移执行
4. 麦轮运动学把车体速度变成四轮速度
5. 四轮速度 PID 变成占空比
6. 占空比送到电机驱动

## 4. 参考工程 A: 麦克娜姆轮小车

参考目录：

- `D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/麦克娜姆轮小车`

它的特点是：

- 结构非常直接
- 位姿控制和麦轮逆解耦合得很紧
- 遥控和位姿目标在一起，适合做快速原型
- 适合低算力 MCU 上跑，因为逻辑短、分支少

### 4.1 关键文件

- [references/麦克娜姆轮小车/smart_car/User/main.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/麦克娜姆轮小车/smart_car/User/main.c)
- [references/麦克娜姆轮小车/smart_car/Hardware/My_PID.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/麦克娜姆轮小车/smart_car/Hardware/My_PID.c)
- [references/麦克娜姆轮小车/smart_car/Hardware/control.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/麦克娜姆轮小车/smart_car/Hardware/control.c)
- [references/麦克娜姆轮小车/smart_car/Hardware/motor.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/麦克娜姆轮小车/smart_car/Hardware/motor.c)
- [references/麦克娜姆轮小车/smart_car/Hardware/encoder.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/麦克娜姆轮小车/smart_car/Hardware/encoder.c)

### 4.2 这个工程在做什么

它的核心逻辑在 [My_PID.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/麦克娜姆轮小车/smart_car/Hardware/My_PID.c)：

- `Kinematic_Analysis()` 根据 `Vx / Vy / Vz` 算四轮目标
- `Incremental_PI_*()` 对每个轮子做速度 PI
- `My_Cascade_PID()` 用位置误差先算目标速度，再进四轮速度环
- `drawcircle()` 是一个圆轨迹的测试例程

这个工程的“简洁”体现在：

- 目标很少
- 状态机很少
- 直接在一个控制文件里完成位置到轮速的闭环
- 适合现场快速试车和调 PID

### 4.3 适合参考的点

- 位置误差直接驱动速度目标，思路很直观
- 轮子方向标志 `flag` 很清楚
- 参数少，便于在调试器里直接看

### 4.4 不适合直接照搬的点

- 位置、速度、姿态、轮速混在一个文件里，耦合较重
- 对异常帧、超时、饱和、模式切换的保护较少
- 迁移到无人机时不能直接沿用麦轮逆解，必须改成飞行器控制分配

## 5. 参考工程 B: 速度位置串级 PID

参考目录：

- `D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/速度位置串级PID`

它的特点是：

- 非常适合入门理解“外环位置、内环速度”
- 代码少，闭环结构清晰
- 调参变量直接暴露，全局变量容易在 IDE 里看
- 很适合作为“把轮子先跑稳”的参考模板

### 5.1 关键文件

- [references/速度位置串级PID/User/main.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/速度位置串级PID/User/main.c)
- [references/速度位置串级PID/System/Timer.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/速度位置串级PID/System/Timer.c)
- [references/速度位置串级PID/Hardware/pid/pid.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/速度位置串级PID/Hardware/pid/pid.c)
- [references/速度位置串级PID/Hardware/encoder/encoder.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/速度位置串级PID/Hardware/encoder/encoder.c)
- [references/速度位置串级PID/Hardware/motor/motor.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/速度位置串级PID/Hardware/motor/motor.c)

### 5.2 这个工程在做什么

它的闭环结构在 [System/Timer.c](D:/CYT4BB7_Library/Example/Motherboard_Demo/car_control/references/速度位置串级PID/System/Timer.c)：

- 定时器中断里周期执行控制
- `expect_speed`、`expect_position` 是外部给定
- `Read_Encoder()` 读当前编码器
- `PID_Position()` 先把位置误差变成速度目标
- `PID_Speed()` 再把速度误差变成 PWM
- `Pwm_Out()` 输出到电机

这就是很经典的“位置环套速度环”的串级结构。

### 5.3 适合参考的点

- 位置和速度的层次清楚
- 调试时可以直接改 `expect_speed`、`expect_position`
- 适合低资源 MCU
- 很适合做“先让轮子一致转起来”的最小闭环模板

### 5.4 不适合直接照搬的点

- 控制功能集中在中断里，后期扩展会比较快变复杂
- 只适合单轴/单电机思路，迁移到四轮或无人机时需要重构分配层

## 6. 当前工程和参考工程的差异

### 6.1 当前工程更像什么

当前工程更像“工程化底盘控制框架”：

- 有遥控协议
- 有导航协议
- 有模式管理
- 有四轮 PID
- 有姿态锁定
- 有显示和状态上报

它比参考工程更完整，但耦合也更重。

### 6.2 参考工程更像什么

参考工程更像“实验台代码”：

- 少模式
- 少保护
- 少抽象
- 适合快速验证一个控制思想

## 7. 如果迁移到无人机，哪些可以直接保留

可以保留的：

- 遥控帧解析方式
- 左/右摇杆的输入语义分层
- IAR Watch 调参方式
- 超时保护和状态显示思路
- “输入层 / 控制层 / 输出层”三段式结构

需要替换的：

- 麦轮逆解 `mecanum_inverse()`
- 四轮速度 PID 到电机占空比的输出方式
- 轮子目标速度生成逻辑

无人机里，输出层不再是“轮速分配”，而要换成：

- 姿态控制
- 油门/电机混控
- 俯仰、横滚、航向分配

也就是说，遥控器输入可以复用，但“把输入变成电机输出”的那一层必须改成无人机专用控制分配。

## 8. 建议的后续迁移路线

1. 先把遥控协议保持不变，只抽出输入层
2. 把 `left stick`、`right stick`、按键的语义做成统一映射表
3. 把“速度控制”和“位置控制”分开
4. 把执行对象从麦轮底盘替换成无人机姿态控制
5. 保留调试显示和 IAR Watch 变量，方便先做地面验证

## 9. 结论

如果你的目标是“把这套遥控逻辑迁移到无人机”，最值得复用的是：

- 遥控协议解析
- 输入语义拆分
- 状态机
- PID 调参方法
- 调试显示与 Watch 变量

最需要重写的是：

- 麦轮运动学
- 轮子速度分配
- 电机输出分配
